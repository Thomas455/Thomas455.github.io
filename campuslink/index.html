CampusLink 校园网认证助手

WPF 桌面程序 · .NET Framework 4.8 · 面向锐捷 SAM+ / eportal 门户 · 当前版本 v1.3.0

把浏览器里反复点来点去的校园网认证，变成桌面上一个常驻的小工具：开机自动登录、掉线自动重连、MAC 无感注册，顺便告诉你「现在在线的到底是谁」。

系统要求：Windows 10（1903 或更高）/ Windows 11；.NET Framework 4.8 在这些版本上已内置，更旧的系统需要自行安装。程序清单要求管理员权限（涉及网卡状态），双击会弹 UAC 确认。自动更新只认 -win.zip，Setup.exe 会被忽略（避免把安装器当成主程序覆盖），所以老用户升级不用重装。

这是什么

很多高校的校园网走的是锐捷 SAM+ / eportal 门户：没认证时访问任意网页会被 AC 拦下来 302 到门户页，填学号密码、点登录，之后才放行。麻烦的地方在于——每天开机都要来一遍，掉线了还得重来，多台设备/多个账号切来切去很容易搞混「现在到底是谁在线」。

CampusLink 把这条链路做成了一个本地 Windows 客户端：探测拦截 → 抓 queryString → 登录 → 按 keepaliveInterval 保活 → 下线，再补上多账号、网卡绑定、无感 MAC、学校预设、自动重连、分级通知、协议诊断和自动更新。界面用 WPF-UI，数据落在 %APPDATA%\CampusLink。

当前内置的学校预设是广州大学·大学城校区（门户 222.201.54.55，自助服务 222.201.54.23:8080，默认密码模板 {uid}@Gzhu）。别的学校可以自己建预设：门户地址不同，协议是同一套。

使用前提：本工具只用于你本人或已获授权管理的账号，所有自动化请求都以本机、本账号发出。请遵守学校网络使用规定，不要用它批量尝试他人账号。程序与广州大学、锐捷网络均无隶属关系，不代表官方立场。

功能

核心认证链路

探测被 AC 拦截的 302，从 Location 里取 index.jsp? 之后的 queryString，然后登录、按 keepaliveInterval 定时保活、下线，全部走门户的 InterFace.do?method= 接口。

认证保活

认得出「现在是谁在线」

MAC 已免认证时，从成功页 success.jsp?userIndex= 拿到 userIndex（它是 会话_IP_学号 的十六进制），再调 getOnlineUserInfo 查出真实账号。与本账号不一致时卡片黄标警告，不会让你以为「已登录」。

在线识别userIndex

账号信息结构化

按 userIndex 拉取账号、网络（IP / MAC / 门户 / 是否本账号）、套餐与余额、门户通知、会话，分组展示；ballInfo 这种「JSON 数组的字符串」会二次解析并格式化（金额加 ¥、时间戳转本地时间、设备数加「台」），可复制、可看原始 JSON。

账号信息ballInfo

学校预设

「学校相关」的配置抽成预设：学校名称、门户地址、自助服务地址、默认密码模板（{uid}@Gzhu）。内置「广州大学·大学城校区」，可新建 / 设为当前 / 删除 / 导入导出，一个预设一个 json，删了下次启动自动恢复内置项。

预设可分享

MAC 无感 + 多账号

登录后调 registerMac 注册无感认证，cancelMacWithUserNameAndMac 解绑；MAC 直接取账号绑定的网卡，不用手填。多账号各自绑定一块网卡（决定认证 MAC 与源 IP）和独立门户地址，支持一键全部登录、强制下线全部会话。

无感认证多账号

常驻自动化

启动自动登录、掉线探测自动重连、登录后自动注册 MAC。加上托盘图标与菜单、开机自启、关闭窗口最小化到托盘、单实例运行（第二次启动只唤醒已有窗口），以及按天滚动的日志。

自动重连托盘开机自启

分级通知

所有操作反馈统一走窗口右下角的通知：绿（成功）/ 黄（注意）/ 红（失败）/ 蓝（信息），自动消失、可手动关闭。卡片上只留持久状态（在线 / 待认证 / 离线），不再被一闪而过的文字刷掉。

通知可读性

数据与隐私

密码用 DPAPI（ProtectedData.Protect，CurrentUser）加密存储，换机器 / 换用户都解不开。日志写入前对 password 等字段脱敏，账号只写显示名称或学号后 3 位，userIndex 只保留前 8 位；启动时还会清洗历史日志。

协议实现要点

统一入口：POST http://<门户>/eportal/InterFace.do?method=，表单提交。编码方式按接口区分——这一步最容易踩坑，所以每条都写清楚。

接口方法编码 / 说明
探测GET http://<门户>/读取原始 302 的 Location，取 index.jsp? 之后的查询串；返回 redirectortosuccess.jsp 即判为在线。原始串不伪造
登录loginuserId / password / service / queryString / validcode 走双重 encodeURIComponent；成功后保存 userIndex 与 keepaliveInterval
保活keepaliveuserIndex 单次编码，按 keepaliveInterval 周期调用（默认 120s）
下线logout / logoutByUserIdAndPass单次编码；后者用于「强制下线全部」
无感registerMac / cancelMacWithUserNameAndMacMAC 归一化为 12 位大写十六进制
只读pageInfo / getServices / getOnlineUserInfo用 queryString / userIndex 取信息

响应解析

优先 JObject.Parse；失败时截取 {...} 重试；再失败用正则抠 "result":"..."。文本解码优先严格 UTF-8，失败回退 GB18030——门户页面本身是 GBK。

密码加密（passwordEncrypt）

自动模式会先读 index.jsp 的隐藏字段 passwordEncrypt、publicKeyExponent、publicKeyModulus，再决定明文还是 RSA；现场判断不准时可以手动切「强制明文 / 强制 RSA」。RSA 分支是照着门户前端 RSAUtils.encryptedString 复刻的：

密码 + 分隔符（> 或 >>）+ MAC
  → 整串反转
  → 按 16 位 digit 小端分块
  → 无填充 ModPow
  → 定长十六进制串提交

资料里 > 和 >> 两种分隔符都出现过，默认 >，设置里可改。

登录状态语义

卡片状态含义
在线真的走通了 login，拿到 userIndex，账号密码已通过门户校验
在线·免认证门户返回 redirectortosuccess.jsp，这块 MAC 已被 AC 放行。没有校验密码，但会识别当前在线的真实账号并标注「本账号 / 非本账号」
待认证拿到了 queryString，还没登录
离线 / 异常已下线 / 探测失败或接口报错

快速上手

  1. 电脑连上校园网，先不要用浏览器登录。
  2. 「设置 → 学校预设」确认当前启用的是「广州大学·大学城校区」（首次启动会自动启用；别的学校先新建自己的预设）。
  3. 「账号」页 → 添加账号：填学号、密码，选一块正在联网的网卡；门户地址会按当前预设自动带出。
  4. 保存后点卡片上的 登录；成功后可再点 无感注册，让该网卡的 MAC 之后长期直通。
  5. 要改账号：点卡片上的 编辑；删除账号在编辑面板里点「删除账号」（二次确认）。
  6. 看当前网络的详细信息：「账号信息」页 → 刷新信息。
  7. 常驻使用：设置里打开 开机自动启动、关闭窗口时最小化到托盘、掉线自动重连。
一个容易误解的地方：如果门户已经显示「已在线」，说明这个 MAC 已在免认证状态，此时点「登录」不会校验密码，卡片显示 在线·免认证。想验证密码对不对，得先解绑 MAC 让 AC 重新拦截。

已知限制

关于验证范围：协议层由自带 mock 门户的 65 项自动化测试覆盖（编码、MAC、DPAPI、RSA、探测、登录、保活、无感、下线、账号信息、预设、脱敏、整包更新）。但真实账号密码登录没有做端到端验证——测试时那台机器已处于免认证状态，门户不会下发 queryString，走不到登录接口。
项目状态说明
真实 passwordEncrypt 取值未确认资料未拿到现场登录页隐藏字段；已提供自动 / 强制明文 / 强制 RSA 三种模式和 >、>> 两种分隔符，可在诊断页核对
服务列表空现场 getServices 返回空数组，service 参数默认留空；报「请选择服务」时从诊断页取服务名填进账号设置
自助服务已移除验证码需人工识别，收益低；改为「账号信息 → 自助服务」在浏览器里操作
同一网卡多账号互相顶掉真实多账号聚合需要每个账号绑定不同网卡
托盘图标Win11 默认折叠依赖 WinForms NotifyIcon；设置页有「打开任务栏设置」直达按钮
密码校验受限MAC 已注册无感时门户不下发 queryString，登录接口走不到，程序无法校验密码
管理员权限必需清单 requireAdministrator，用于修改网卡相关状态；单实例互斥只在同一会话内生效

构建、打包与测试

需要 Windows 10/11 + .NET Framework 4.8 目标包，以及 Visual Studio 2026（18.x）或 MSBuild；NuGet 会还原 WPF-UI 4.3.0 与 Newtonsoft.Json 13.0.3。

# 在 CampusLink.csproj 所在目录
msbuild CampusLink.csproj -t:Restore,Build -p:Configuration=Release
# 产物：bin\Release\CampusLink.exe
# 一条命令生成安装程序 + 更新包（在仓库根目录）
powershell -ExecutionPolicy Bypass -File tools\package.ps1
# dist\CampusLink-Setup-<版本>.exe
# dist\CampusLink-<版本>-win.zip

编译安装程序需要 Inno Setup 6；没装时脚本只出 zip。

协议层测试（自带 mock 门户，不需要真机联网）：

cd CampusLink
msbuild CampusLink.csproj -t:Restore,Build -p:Configuration=Debug
cd ..\tests\CoreTests
msbuild CoreTests.csproj -t:Restore,Build
.\bin\Debug\CoreTests.exe
# 通过 65 项，失败 0 项

发布：推 v* tag 触发 GitHub Actions（构建 → 生成 zip → 编译 Setup → 创建 Release 并上传两个附件）；workflow_dispatch 只构建、不发布。构建前会按 tag 改写 AssemblyInfo 的版本，保证「关于页显示的版本」和 tag 一致，自动更新不会反复提示同一个版本。
